## 现有证据与新的分组诊断

当前选用方法的本地参考总分为 57.69；2026-10-20 的官方赛后总分为 61.17。
两者来自不同数据集，不能作直接增益比较。历史结果见 [优化报告](OPTIMIZATION_REPORT.md)。

本次重新汇总 16 篇开发文献的既有逐患者结果，得到下表；按金标准表型数量分组仅用于诊断，推理时不能使用该分组标签。

| 开发患者分组 | 人数 | 原基线患者 Macro F1 | 当前模型患者 Macro F1 | 观察 |
| --- | ---: | ---: | ---: | --- |
| 金标准为空 | 4 | 100.00 | 0.00 | 当前模型给四人添加了共 8 个错误表型 |
| 金标准 1–3 个表型 | 23 | 29.93 | 24.62 | TP 14→18，FP 12→57，精度损失明显 |
| 金标准至少 4 个表型 | 27 | 37.56 | 53.17 | 较丰富患者集合受益较大 |

拟合部分的 155 位患者中有 8 位空集合患者，分布于 7 篇文献。因此应优先简单的集合决策与跨文献验证，避免针对四个开发患者写专用规则。
空集合表示本任务没有标注的阳性表型，不能等同于患者健康。官方当前 README 明确双方集合均空时患者 P/R/F1 为 1。
[官方任务和评分说明](https://github.com/DUTIR-BioNLP/PatientPheX)

实体方面，531 个漏检单元中有 363 个完全没有重叠候选（68.36%），122 个为边界错误。
患者关联方面，231 个漏检中有 181 个概念未抽取（78.35%），另外 50 个概念已经存在但没有正确分配。
固定当前非否定文档候选集合，患者关联可覆盖的正例数为 237+50=287 / 468，即条件召回上界约 61.32%。
这是当前候选集合下的诊断量，扩展候选后会改变，也不是模型能够实际达到的承诺。

另外，冻结优化脚本的关系训练使用了该拟合文献自身学习的别名生成候选，验证文献仍保持隔离。
这不是发现开发标签泄漏；它提示一种待检验的训练/推理候选分布差异：训练候选可能更完整、更准确。
源码证据在 runs/optimization_v1/source/run_optimization.py 的关系训练部分。

可复核的分组汇总、输入与诊断来源哈希保存于 IDEAS_DIAGNOSTIC_20261021.local.json。
这些均是已观察开发集上的事后分析，没有产生新的验证成绩。

## 三个追问

1. 为什么 Micro 上升而 Macro 下降？现有分组统计显示，表型较多患者获得收益，而空集合和少表型患者承受较多误报。
2. 为什么只加患者状态词没有解决？补充实验中四位空集合患者依旧全部被误加表型；该实验没有改善集合输出决策。更深的因果解释尚未验证。
3. 为什么只改关联器仍不够？多数患者漏检概念根本不在抽取结果里；分配已有候选无法恢复这部分遗漏。

## 收敛后的五个方向

### 1. 交叉拟合候选 + 患者集合决策：最先开展的低成本方向

先把 64 篇拟合文献分组。每份关系训练候选由没用过该篇文献标签的抽取器产生，
再训练关系模型，使其接触真实的抽取遗漏和误报。用于拟合校准器、路由器的分数也必须来自折外预测。
在某折评估整套方案时，其实体、关系和校准组件都只能使用该折的训练文献，不能把全局折外数据不加区分地回灌。

在逐项分类之后增加患者层决策：是否有充分证据输出阳性表型、输出多少项、哪些候选需要复核。
可用特征包括最高分、分数间隔、显式患者证据比例、规则/分类器分歧和候选数量；不能使用真实表型数量。
先比较一两个简单阈值或低参数校准器，再决定是否需要基数预测器。
已有患者等权训练与状态特征搜索未带来可采用的外层增益，不重复把它们当作未经检验的新方案。

核心评价：总分、患者 Micro/Macro、空集合误报、少表型患者精确率，以及按文献的增益分布。
“无证据则保守输出”应允许被语义召回分支补充证据，避免仅靠空输出改善一小部分患者。

### 2. 混合实体召回 + HPO 上下文重排：更大覆盖潜力

将词典候选与神经 span 候选合并。神经模型提出原文连续片段，代码负责回到原文校验位置；
之后在固定版本 HPO 中检索多个概念，结合上下文重排，并允许无法映射的情况。
实体发现与概念规范化要分别评估：只有检索器没有新的 span 来源，无法自动解决词典完全漏检。
HPO 层级可用于表示共享、生成困难负例和消歧，不自动把所有祖先概念加入答案。

可参考 PhenoTagger 的本体驱动候选训练，以及 BioSyn/SapBERT 的同义词表示和概念链接思路。
它们是已有技术来源，不把直接组合这些组件称为新颖贡献。
[PhenoTagger](https://github.com/ncbi-nlp/PhenoTagger)、[BioSyn](https://aclanthology.org/2020.acl-main.335/)、
[SapBERT](https://aclanthology.org/2021.naacl-main.334/)。

版本要点：PhenoTagger 公共 README 的模型更新使用 HPO 2023-10-09，而本比赛固定 2026-06-23；
拟采用时需基于比赛本体重建/核验词典及概念模型。仓库附带的外部人工标注语料不作为本比赛训练数据。
[上游版本说明](https://github.com/ncbi-nlp/PhenoTagger#updates-2023-12-19)

核心评价：新增真阳性、新增误报、候选 Recall@K、精确边界 F1，以及是否带动患者指标。

### 3. 患者证据链 + 同文献困难负例：关联质量主方向

为每个指定患者检索自己的提及、病例段落、相关分节和可能的跨段共指，形成带原文位置的证据集合。
对候选关系输出患者 ID、候选概念 ID、证据片段编号和阳性/否定/无法判断状态；代码核验 ID、位置和引用文本。
证据可定位是必要检查，不等同于证据已经支持该关系，仍需模型或人工抽样核验语义归属。

训练时，给定的关联标签是患者—概念集合，并没有每条关系的完整证据位置标注。
因此同一概念的多次提及应视为一个证据袋，避免把该概念的每一次出现都伪标成某患者的正例。
使用训练集明示关系构造高置信样本，并把其他患者的相同概念、疾病背景段落等作为困难区分对象。
一个概念可以正确属于多位患者，不能强制所有患者之间单选，也不能把所有家族史一律删除。

任务 1 仍保留其定义范围内的文档表型；患者证据筛选服务于任务 2，不能据此从任务 1 删除其他患者或背景中的有效实体。
可以选择 Qwen3-8B 做受约束的局部判断；其官方模型卡列出 8.2B 参数，且组织方基线已经采用该家族。
[模型卡](https://huggingface.co/Qwen/Qwen3-8B)、[比赛基线说明](https://github.com/DUTIR-BioNLP/PatientPheX#baseline系统)。

核心评价：同文献串患者错误、两种患者 F1、证据语义正确率，以及 ID/列表顺序变化时的输出一致性。
先比较原文段落与局部证据组织的贡献，再增加图模型或更长推理，确保复杂度有收益。

### 4. 边界、复合概念与否定范围：可拆分的精修方向

122 个边界漏检说明只纠正 HPO ID 不足以满足提及级精确匹配。
从官方训练文献学习跨度边界、并列描述、一对多概念和否定范围，保持 Unicode 原文坐标。
单独做“边界修正”“复合映射”“否定范围”三个消融，检查对患者关联的连带影响。
不依据当前开发错例手工添加专用答案或更改评分规则。

### 5. 定向小模型微调与按需复核：在前四项出现信号后开展

用官方训练文献派生局部实体或归属样本，进行 <=10B 模型的参数高效微调。
先比较未微调的相同基础模型、局部监督微调、仅疑难项复核，记录完整耗时和显存。
疑难项复核不能取代实体召回分支：从未被候选生成器发现的表型无法进入复核队列。
现有全文仅 80 篇，派生出大量片段也不等于获得大量独立文献样本；所有划分继续按文献组进行。
本轮未选择具体训练配置、启动 GPU 或下载权重。

## 推荐主线与三个最小实验

两句话研究表述：现有系统给表型丰富患者补回了许多概念，却给少表型患者引入较多错误，造成 Micro 与 Macro 的取舍。
我们拟用更接近推理分布的关系训练候选，以及以患者证据为依据的集合决策，检验能否同时改善两种指标。

这首先是一条可检验的比赛改进路线。若希望形成论文贡献，需要进一步确认方法新颖性、跨文献稳健性及额外允许使用的验证数据，不能仅凭组合现有模块或开发分数宣称创新。

优先冻结以下三个对照实验，均从相同当前版本出发：

1. 只改变关系训练候选的生成方式，比较当前拟合内候选与交叉拟合候选；实体配置和输出决策保持一致。
2. 固定关系模型，对比全局阈值、简单规则/分类器融合、患者集合决策；校准和选择只用拟合部分折外结果。
3. 做两个组件的 2×2 消融：原版、仅候选分布对齐、仅集合决策、两者联合；报告逐文献收益和所有患者分组。

最强反对意见：空集合问题可能只来自一篇特殊开发文献，新的集合模型可能只是过拟合它。
应对：该文献不用于拟合门控规则；方法选择先看 64 篇拟合部分的分组验证，并报告文献级差异和非空患者表现。
开发集此前已反复观察，后续结果继续称为开发比较。线上 B 集反馈也已被观察，不能用提交分数反复调参后再宣称独立测试。
