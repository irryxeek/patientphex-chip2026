# 第二轮优化协议

2026-10-20，结果观察前固定。沿用 `runs/baselines_v1` 的 64/16 篇划分及参考评分代码，
本轮不修改金标准或评分定义。16 篇已是开发集，不能声称为未触碰测试集。

## 候选方案

实体侧在 64 篇拟合文献内做四折分组验证，比较以下预定配置：

1. 原始训练别名基线。
2. 训练别名的最低单词长度约束、训练语料中完整边界匹配的精度过滤（阈值 0.25/0.50）。
3. 上述方案增加轻量单复数归一化。
4. 从推理文献自身的明确括号定义恢复缩写；不读取推理文献标签。

选择标准为内层合并预测的 mention F1 与 document F1 均值。
确定配置后才运行外层 16 篇验证。所有尝试和未选配置保留。

患者侧将每个“文献—指定患者—候选概念”作为二分类样本，使用数值上下文特征：
同句/段内显式指称、患者距离、其他患者竞争证据、章节、跨段最近患者及提及频次。
不将文献 ID、患者 ID 或 HPO ID 本身作为记忆特征。原始文本仍仅用于提取上下文证据。
比较原关联规则与小型梯度提升分类器；分类器在每折的拟合文献上训练，
阈值仅从内层留出概率选择（0.20、0.30、0.40、0.50、0.60）。

分类器的训练实体候选由该折训练文献构建的词典产生，属于拟合侧特征；
验证文献与其别名不参与拟合。该设置可能有拟合/验证候选分布差异，必须通过内层验证检查。
依据内层 patient micro/macro F1 均值选择关联方法及阈值。

## 外层核验与交付

- 只在选择完成后比较原基线、改进实体加原关联规则、完整改进系统。
- 保存分组件 F1、逐文献诊断、配对文献 bootstrap、评分敏感性和全部源代码。
- 检查输入标签污染、字符偏移、全患者覆盖、原始文件哈希及重载可复现性。
- 外层结果若退步，保留旧版为默认候选；若改进，使用全部 80 篇拟合并导出新的 A/B 文件。
- 该规则下的外层结果仍是开发比较，不是线上成绩或泛化保证。

CPU 方法不依赖 GPU。Qwen3-8B 实验取决于本任务的设备范围；资源确认期间继续执行上述流程。
分类器使用本地 scikit-learn 1.7.2；接口参考
[HistGradientBoostingClassifier](https://scikit-learn.org/1.7/modules/generated/sklearn.ensemble.HistGradientBoostingClassifier.html)。
