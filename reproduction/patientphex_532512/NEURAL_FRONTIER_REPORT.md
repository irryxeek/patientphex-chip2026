## 方法选择

依据 [前沿调研](FRONTIER_RESEARCH_20261022.md) 和既有错误分析，执行
[预先固定的实验协议](FRONTIER_EXECUTION_PROTOCOL.md)。协议、代码和输入哈希已保存到
`runs/neural_frontier_v1/`；完整实验采用该目录的冻结源码。

| 模块 | 实现 | 针对的问题 |
| --- | --- | --- |
| 候选跨度 | BioLinkBERT-base 的 BIO 分类，与原词典候选合并 | 现有系统的漏召回和边界错误 |
| HPO 归一化 | 固定 SapBERT 的 CLS 向量，训练折别名优先，再按相似度和概念间差距筛选 | 未见表述及同义变体 |
| 患者归属 | 独立 BioLinkBERT 分类器读取患者与表型证据，融合原梯度提升概率 | 多患者串联、跨句证据和低表型数量患者误报 |

同赛题领先方法采用多源识别、SapBERT 检索及关系特征融合；本轮先以小编码器实现可检验的对应模块。
这不是冠军完整系统的复现，也未将文献中的收益当成本项目的收益。
两个预训练模型均约 0.11B，使用公开预训练权重与官方训练标注；没有引入已在全量
PatientPheX 上训练的第三方权重、外部人工表型标签或外部付费模型调用。

本轮保留原 64/16 篇分组及内层四折。实体配置共 13 个，关系配置包括原版及 20 个融合候选。
先在内层选定，再评估外层；采用要求为总分严格提高且患者 Macro 不下降。
开发集已被既往实验使用，结果不能表述为未触碰测试集性能。
方案通过采用条件后，已完成全量训练、A/B 生成与打包；独立进程复算通过后提交了一次赛后评测。

## 已实际执行

- 下载并核验 BioLinkBERT-base 与 SapBERT 的固定 revision、文件 SHA256；权重保存在现有 SSD 根下。
- 在 CPU 上建成固定 HPO 语义索引：19,120 个概念，41,108 个名称/同义词与概念的配对，
  768 维归一化向量；缓存及独立进程重载审计见 `preflight/ontology_audit.json`。
- 实现训练、窗口跨度解码、不同 HPO 概念的语义间距、证据构造、融合选择、消融、打包和独立重载入口。
- 固定原文字符偏移、金标准隔离、患者身份及版本校验；新增 10 项回归测试，项目共 **92 项 CPU 测试通过**。
- 三个新增 Python 实现文件和新测试文件通过仓库的 `pre-commit ruff`、`ruff-format` 检查。
- NER CPU smoke 完成 2 个真实优化步骤，权重保存并在另一篇文献上重载推理。
  该极短 smoke 输出 0 个跨度，不能用来证明识别质量；正式模型从公开预训练权重重新开始。
- 关系 CPU smoke v2 包含 3 个候选、2 个正例，完成 2 个更新步骤，随后在另一篇文献上生成
  2 个有效概率并完成与原模型的融合。该 smoke 仅检查执行链路。
- 初次关系 smoke 的对照模型拒绝了训练文献，原因是 smoke 脚本漏写显式训练诊断标志。
  保留原检查结果和模型后修正脚本；正式验证仍禁止训练文献重叠。

模型与 smoke 清单见运行目录的 `preflight/verification.json`。没有改写原始标注、旧模型、
旧预测、官方成绩或既往失败实验；上述预检查阶段仅使用 CPU，未终止共享服务。
NER 与关系 smoke 权重分别有 199/201 个张量，检查未发现非有限值；这只证明保存结果的结构完整性。
